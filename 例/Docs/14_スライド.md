# 発表スライドの決めごと

ピッチ用スライド（提出物5）を作るときの決めごと。2026年11月8日に作成。

**この文書の使い方：** チームのだれが、どの AI（Claude・Gemini・ChatGPT など）を使って作っても、同じ方針のスライドになるようにする。スライドを作る・直す前に、この文書を AI にそのまま渡す。直したい方針があれば、スライドではなく先にこの文書を直す（正本はこのファイル）。

## 2. 中身の決めごと（アプリについて）

スライドに書くアプリの中身は、次の文書を正とする。AI に作らせるときは、これらも一緒に渡す。

- 何を・誰のために：`1_方向.md`
- できること・扱わない範囲：`2_今できること.md`
- 仕組み（AI とコードの線引き、技術構成）：`3_仕組み.md`
- テストの数字：`7_テスト.md`（**発表の前に `npm run eval` を回して最新にする**）

守ること：

- 今のアプリは「**会話を聞くだけ**」。メニューは「会話」と「履歴」の2つ。「伝える前に確かめる（送り手の確認）」はスライドで機能として見せない。
- **AI は答えを書かない**。言葉の意味や理由は、話した本人に聞く。
- 数字・言葉・インタビューの引用は、文書にあるものだけを使う。作らない、盛らない。
- 決まっていないもの（アプリ名・チーム名・メンバー・デモの場面）は［アプリ名］のように空欄で残す。

## 4. 振り返り（2026年11月8日・Tomo）

### 良かったこと（次の版でも残す）

- **5枚目「使い方」：** 使う人の動きが順番（1〜4）に並んでいて分かりやすい。→ 手順は番号つきで横に並べる形を続ける。
- **8枚目「AI は答えを書かない」：** AI・プログラム（コード）・人のそれぞれがすることが分かれて書かれていて、とても良い。→ 役割を「だれが何をするか」で分けて見せる形を続ける。

### 悪かったこと（次の版で直す）

- **9枚目「Google の技術」：** 箇条書きのカードだけで、エンジニアには仕組みが伝わりにくい。→ **フローチャート（処理の流れの図）にする。** 下の「9枚目の図」のとおり。

**出典の確認（2026年11月8日）：** 「技術スタックを図にする」という指定は、キックオフのスライド（Drive「[DF Hack26] Kickoff Slide.pdf」）の「提出資料サンプルの紹介」に、例として「Google Cloud アーキテクチャ図」と「公式アイコン：cloud.google.com/icons」が載っている。これは**提出物（プロダクト説明ドキュメントの「4. アーキテクチャ図」と Drive フォルダ）向けのサンプル**で、ピッチ用スライドに図を入れることを必須とする書き方ではない。ただし、審査の「Google 技術が中核で有効に機能しているか」を伝えるのに効くので、スライドにも入れる。

### 9枚目の図（次の版）

1枚に、1つの発言がどう流れるかを、左から右（または上から下）に描く。箱には「何が・どこで」を書き、Google の技術の箱は公式アイコン（cloud.google.com/icons）を使う。

```
[医師が話す]
   ↓
[聞く人のスマホ（Chrome）] 音声認識で文字にする・空白をコードで消す
   ↓  発言と直前の会話（職種：発言）
[Cloud Run] Next.js のアプリ（/api/detect）
   ↓
[Vertex AI の Gemini] 言葉・読み・種類・まだ話されていない点・話した人・聞き間違いの直しを JSON で返す
   ↓
[コードの検査（Cloud Run の中）]
   ・形が違えば捨てる（zod）
   ・数字が変わる直しは捨てる
   ・種類と、並べる点と順番はコードが決める
   ↓
[聞く人のスマホ] 「分かりますか？」→ はい／いいえ → 質問リスト
```

図で伝えること：

- Gemini が中核にいること（言葉を見つけるのは辞書ではなく Gemini）。
- AI の出力を、そのまま画面に出さずにコードが検査していること（8枚目とつなげる）。
- API キーを持たず、Cloud Run のサービスアカウントで Vertex AI を呼んでいること。
- 図の下に、選んだ理由（なぜ Gemini か・なぜ Cloud Run か）とデメリットへの対策を1行ずつ。中身は `11_プロダクト説明（下書き）.md` の 3.2 の表を使う。

構成図の下書き（`構成図.svg`）と、提出用のアーキテクチャ図（担当 Tomo）と、同じ図にそろえる。

## 5. 見た目の決めごと

- 1枚に言いたいことは1つ。箇条書きより、順番・表・図・大きな数字で見せる。
- 文字は大きく（いちばん小さい文字でも、会場の後ろから読める大きさ）。
- 色：明るい地（生成り）、濃い文字（墨色）、強調はオレンジ1色。アプリの画面の「AI が見つけた言葉」の印（オレンジ）とそろえる。
- 字体：見出しは丸ゴシック（Zen Maru Gothic）、本文はゴシック（Noto Sans JP）。著作物利用シートに書いてあるものを使う。
- 画面の写真は、自分たちのアプリを本物の Gemini で動かしたものだけ。

## 6. 別の AI でスライドを作るときの頼み方（例）

次の文を、この文書と2章の文書と一緒に AI に渡す。

> 添付の「14_スライド.md」の決めごとに従って、ハッカソンのピッチ用スライドを作ってください。中身は添付の文書にあることだけを使い、数字や引用は作らないでください。決まっていない名前は［アプリ名］のように空欄にしてください。3章の構成を元にし、4章の「良かったこと」は残し、「悪かったこと」は直してください。
