# 仕組み

## AIとコードの線引き

ルール4に沿って、AIには文章を書かせ、選択と判断はコードがする。AIが判断するのは「この観点で相手がつまずきそうか」の予測だけにする。

| 処理 | 担当 | 内容 |
| --- | --- | --- |
| 受け手の種類 | コード | 送り手が画面で選ぶ（薬剤師／患者） |
| チェックする観点 | コード | 受け手ごとに観点リストを固定で持つ |
| 観点ごとの予測と質問文 | AI | 入力文を読み、観点ごとに「相手が分からなそうか」と、相手が抱きそうな質問文を決まった形式（JSON）で返す |
| 形式チェック・並べ替え・件数の上限 | コード | 形式が崩れた出力を弾き、表示順と最大件数を決める |
| 画面への表示 | コード | 送り手には補足を促す形、受け手には質問リストの形で出す |

### 対面の流れ

| 処理 | 担当 | 内容 |
| --- | --- | --- |
| 送り手・受け手の職種 | コード | 利用を始めるときにホーム画面で1回選ぶ（医師・患者・薬剤師・看護師・介護者） |
| 文字起こし | ブラウザ | ブラウザの音声認識（Web Speech API、無料）で送り手の話を文字にする |
| 前提が必要な用語の検出 | AI | 入力を読み、受け手が理解するのに前提が必要な用語を、決まった形式（JSON）で返す。観点リストが決まるまでは AI の判断だけで探す |
| 「分かりますか？」を出す | コード | 一度答えた語は聞き直さない。質問リストにある語なら、その項目と状態を見せる。見つけたらすぐ、目立たない形で出す |
| 答えた語の記録 | コード | 「はい」「いいえ」の両方を覚えておき、聞き直さないようにする |
| はい／いいえの記録と質問リスト | コード | 「いいえ」の語だけを質問リストのいちばん下に足す。チェックの記録、チェック済みを上へ移す並べ替えもコード |
| キリの判断 | しない | 受け手が自分で決める |
| 疑問への答え | しない | AIは答えを作らない。送り手に直接聞くよう促すだけ |

### 声で2人を分ける（話者分離）の候補（検討中）

| 方法 | 分け方 | 良いところ | 気になるところ |
| --- | --- | --- | --- |
| ブラウザの音声認識（今） | 分けられない | 無料・速い | B の言葉も混ざる |
| Gemini に音声を送る | 数秒ごとの音声を送り、文字起こしと「話者1／話者2」の区別を一緒にさせる | 文字起こしの精度も上がる見込み。同じ Gemini API で済む | 数秒遅れる。区別の精度は日本語で試す必要がある。費用がかかる |
| Google Cloud の音声認識（Speech-to-Text） | 話者分離の機能を使う | 話者分離が専用の機能としてある | 日本語の話者分離に対応しているか、要確認。設定が増える |
| 声を使わない方法 | B が話すときだけボタンを押す（その間は探さない） | 確実・すぐ作れる | B の操作が増える |

ルール3に沿って、作る前に実際の会話の録音で試して確かめる。

## 観点リスト

- **薬剤師向け：** 数量・本数の根拠／使う期間・交換の頻度／何のために必要か／前提となる患者の状態／足りない・余ったときの対応
- **患者向け：** 専門用語／なぜ必要か／いつ・どのくらい（頻度・期間）／してはいけないこと／困ったときの連絡先
- **医師・看護師・介護者向け：** 未定

観点リストは5職種ぶんを後で決める。それまで対面の流れでは観点リストを使わず、AI の判断だけで用語を探す。上の2つは、これまでの案で作ったもの。

## 測る条件

ルール5に沿って、AIの出力は文章を比べず、守られるべき条件を検査する。テスト用の入力を10件ほど用意する。

- 「チューブを2本持ってきてください」（薬剤師宛）→ 観点「数量の根拠」が必ず出る
- 本数の理由まで書いた入力 → 「数量の根拠」は出ない
- 出力が決めた形式（JSON）として読める
- 観点リストにない観点を返さない
- 件数が上限以内に収まる

## 言葉の対応表

この開発で特別な意味で使っている言葉。コード上の名前は、技術構成を決めたら記入する。

| 言葉 | 意味 |
| --- | --- |
| 前提 | 一方は分かっていて、もう一方は分かっていない情報。話す側は「相手も知っている」と思い込んでいる |
| 認識の差 | 前提が共有されていないことで生じるずれ。このアプリが小さくしたいもの |
| 根拠 | 指示の理由。例：チューブがなぜ2本なのか（患者の状態、使用量、交換頻度など） |
| 多職種 | 医師・薬剤師・患者など、立場や知識の違う人どうし。患者も含める |
| 送り手 | 指示・説明を出す側（A）。医師・患者・薬剤師・看護師・介護者のどれでもなりうる |
| 受け手 | 指示・説明を受け取る側（B）。5職種のどれでもなりうる。対面の流れでは端末を持つ |
| 分からない点 | 受け手がつまずきそうだとAIが予測したもの。確定した事実ではなく予測 |
| 補足を促す | 分からない点を送り手に見せ、根拠を書き足してもらうこと。AIは根拠を書かない |
| 質問リスト | 分からない点を、受け手が送り手にそのまま聞ける形に並べたもの。対面の流れでは、受け手が「いいえ（分からない）」と答えた語の一覧で、画面上部に出す。質問できた項目は受け手がチェックし、チェック済みはリストの上へ移る |
| 対面の流れ | 端末1台を受け手が持ち、送り手の話を文字起こしして、難しい語を受け手に確かめる使い方 |
| キリ | 会話の区切り。システムは判断せず、受け手が「今聞こう」と思ったときがキリ |
| 前提が必要な用語 | 受け手が理解するのに前提知識が要る語。難しい語と、観点リストの観点（なぜ必要か・いつどのくらい など）の両方から探す |
| 観点 | 分からない点を探すときの切り口。例：数量の根拠、専門用語 |
| 観点リスト | 受け手ごとに固定された観点の一覧。コードが持ち、AIは増やせない |
| AIとコードの線引き | AIには文章を書かせ、選択と判断はコードがするという分担（ルール4） |
| 測る条件 | AIの出力が守るべき条件。文章どうしを比べず、条件を満たすかを検査する（ルール5） |
| 扱わない範囲 | 作らないと先に決めたもの。「これ入れたら良くない？」と思ったら確かめる |
| MVP | 最初に作る最小の機能。発表のデモで見せる範囲 |

## AIの出力の形

対面の流れ（2026年11月6日、試作で決めた。変えてよい）：

```json
{ "terms": [{ "term": "NSAIDs", "reading": "えぬせいず" }, { "term": "毎食後", "reading": "まいしょくご" }] }
```

- `term`：受け手が理解するのに前提が必要そうな用語。発言に出てきた表記のまま。
- `reading`：ふりがな（ひらがな）。コードは、漢字を含む語で、読みがかなだけのときに使う。説明文などは捨てる。
- コードで検査すること（`app/src/lib/detection.ts`）：JSONとして読める／形が合う／発言の中にある語だけ（AIが作った語や説明文は捨てる）／30文字以内／重複を除く／1回の発言で5件まで。

## AIへの指示文（プロンプト）

置き場所：`app/src/lib/prompt.ts`。要点：

- 送り手と受け手の職種を伝え、受け手が理解するのに前提知識が必要そうな用語を探させる（専門用語・略語・単位、理由・頻度・期間・量などの前提）。
- 発言に出てきた表記のまま、語だけを返させる。言い換え・説明・答えは書かせない。
- 直前の発言3つを参考として渡すが、選ぶのは今回の発言からだけ。

## 画面の文言（仮）

試作で仮に置いた文言。画面に出す文言は人に聞くこと（README）なので、決まったら直す。DESIGN_BASE.md 3章に沿って、命令しない・ボタンは動詞で終える。

- ホーム：「だれと だれが 話しますか」「話す人」「聞く人（この端末を持つ人）」「はじめる」
- 帯：「「〇〇」は分かりますか？」「はい」「いいえ」「「〇〇」を上のリストに入れました」「「〇〇」は分かる、にしました」「取り消す」
- 質問リストが空のとき：「分からなかった言葉が、ここに並びます。聞けたら印をつけられます。」

## 技術構成とデプロイ

2026年11月6日に決定。詳しいコマンドは `app/README.md`。2026年11月6日、Gemini の呼び出しを Google AI Studio の API キーから Vertex AI 経由に切り替えた（クレジットを使うため）。

| 項目 | 決めたこと |
| --- | --- |
| 言語・フレームワーク | TypeScript、Next.js 16（App Router）。画面とAPIを1つのアプリで作る |
| AIのAPI | Gemini を **Vertex AI 経由**で呼ぶ（`@google/genai`、`vertexai: true`）。認証は API キーではなく Google Cloud の認証情報。モデル名は環境変数で切り替える |
| 文字起こし | ブラウザの音声認識（Web Speech API）。無料。受け手の端末で動くかを先に試す（ルール3） |
| AI出力の検査 | zod（`app/src/lib/prediction.ts`） |
| テスト | Vitest（`npm test`）。全チェックは `npm run check` |
| デプロイ先 | Cloud Run（`app/Dockerfile`）。`gcloud run deploy --source app`。サービスアカウントに「Vertex AI ユーザー」の権限を付ける |
| 環境変数 | `GOOGLE_CLOUD_PROJECT`、`GOOGLE_CLOUD_LOCATION`（空なら global）、`GEMINI_MODEL`。秘密の値はない |

コード上の名前（観点ID）は `app/src/lib/viewpoints.ts` にある。AIの出力の形は仮のものを `app/src/lib/prediction.ts` に置いた（`items[]` に `viewpointId`・`likelyUnclear`・`question`）。「AIの出力の形」の章を決めるときに合わせて直す。
