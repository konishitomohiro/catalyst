## 1. プロダクト概要

- **アプリ名**：[アプリ名]
- **ひとことで**：医療・介護の会話の中で、聞く人が「前提が要りそうな言葉」に気づき、その場で話す人に聞けるようにする Web アプリ。
- **カテゴリ**：医療・福祉
- **使う人**：医師・患者・薬剤師・看護師・介護者。話す人と聞く人は、この5職種のどの組み合わせでもよい。端末は聞く人が持つ。

## 2. 解決する課題

### 課題の一文

医療・介護の現場で、指示や説明を受ける人が、話す人の頭の中にある前提（理由・量・頻度・専門用語の意味）を知らないまま動くため、量の過不足や手戻りが起きている。

### 根拠

- **インタビュー**（訪問薬局の薬剤師、2026年11月5日）
  - 「医者からチューブを2本持っていくように言われたが、なぜその本数なのか分からなかった。」
  - 「チューブが足りないと言われて多めに持って行ったら、多すぎて返品された。」
- どちらも、医師の頭の中にある根拠（患者の状態・使用量・交換頻度）が薬剤師に伝わっていないことが原因。
- 話す人は「相手も知っているはず」と思って話す。職種が違うほど知識や見ている情報が違うので、どの組み合わせでも起きる。

### 今の解決方法とその限界

- 今の方法：聞く人がその場で気づいて質問する、あとで電話で問い合わせる。
- 限界：[聞く人は「何が分かっていないか」に自分で気づきにくい。気づいても、会話の流れを止めて聞きにくい。あとから聞くと手戻りになる。※インタビューの言葉で裏づける]

## 3. 解決策

### 主な機能

1. **聞き取り**：話す人の話を、聞く人の端末が文字にする。
2. **前提が要りそうな言葉を見つける**：Gemini が、聞く人の職種から見て分かりにくそうな言葉を見つけ、画面の下に「〇〇は分かりますか？」とそっと出す。
3. **質問リスト**：「いいえ」と答えた言葉が画面上部に残る。聞く人は好きなときに話す人へ直接質問し、聞けたら印をつける。

### 使う流れ

1. ホームで、話す人と聞く人の職種を選ぶ。
2. 話す人が話す。システムが文字にする。
3. AI が前提の要りそうな言葉を見つけ、画面の下の帯に「分かりますか？」を出す。会話はさえぎらない。
4. 聞く人が「はい／いいえ」で答える。「いいえ」は質問リストへ。答えは5秒間取り消せる。
5. 会話のキリが良いところで、聞く人が話す人に直接質問し、聞けた言葉に印をつける。

## 4. 選定理由（Own the Why）

### 4-1. 検討した案と比較

| 案 | 良い点 | 悪い点 | 採用／不採用の理由 |
| --- | --- | --- | --- |
| **聞く人の端末で会話を聞き、分からない言葉を本人に確かめる（採用）** | 会話を止めない。AI の予測を、本人の「はい／いいえ」で確かめられる | 声を聞き取る精度に左右される | 根拠を一番持っている話す人に、聞く人が直接聞ける形になる |
| 話す人が指示を入力し、AI が「補足しますか？」と促す | 話す前に直せる | 話す人の入力の手間が増える。対面の会話に入れない | 最初の案。対面の会話でそのまま使えないため、MVP から外した |
| AI が言葉の意味や理由を説明する | 聞く人がすぐ分かる | 医療では、AI の誤った答えが命に関わるおそれがある | 採用しない。答えは必ず話した本人に聞く |
| システムが会話の区切りを判断して質問を促す | 聞き忘れを減らせる | 会話に割り込む | 採用しない。区切りは人が決める |

### 4-2. 技術の選定理由

| 用途 | 採用した技術 | 比べた技術 | 採用した理由 |
| --- | --- | --- | --- |
| 実行基盤 | Cloud Run | Firebase Hosting＋Functions、App Engine | 画面と API（Next.js）を1つのコンテナでそのまま公開できる。使われていないときは止まり、費用を抑えられる |
| AI | Gemini（Vertex AI 経由） | Google AI Studio の API | 日本語の会話から専門用語と読みを拾い、決めた形（JSON）で返せる。Vertex AI 経由なら配られた Google Cloud クレジットが使え、API キーを持たずに済む |
| 画面と API | Next.js＋TypeScript | Python FastAPI＋素の HTML、Flutter | 画面と API を1つのアプリで作れ、型で間違いを減らせる |
| 文字起こし | ブラウザの音声認識（今） | Gemini の音声入力、Speech-to-Text | 無料ですぐ試せる。精度が足りなければ Gemini に置き換える（[結果を書く]） |
| AI 出力の検査 | zod | 手書きの検査 | 決めた形を1か所に書け、テストしやすい |

## 5. 安全性・倫理への配慮

- **AI は答えない。** 言葉の意味や疑問への答えは書かせない。答えは必ず話した本人に聞く。
- **AI の出力をコードで検査する。** 発言の中にない言葉（AI が作った言葉・説明文）は捨てる。読みはかなだけを使う。件数に上限をつける。
- **AI の予測をそのまま事実にしない。** 見つけた言葉は、聞く人が「はい／いいえ」で確かめる。
- **会話を保存しない。** 画面を閉じるか、ホームに戻ると消える。
- **費用事故・悪用を防ぐ。** 呼び出し回数と1回の長さに上限をつけ、Cloud Run のインスタンス数を絞る。
- **誰が持っても使える。** ふりがな、色だけに頼らない表示、押しやすいボタン、取り消せる操作（ユニバーサルデザイン）。
- **デモでは架空の会話だけを使う。**

## 6. 想定する拡張

- 声で2人を分け、話す人の言葉だけから探す
