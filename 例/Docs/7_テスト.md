# テスト（測る仕組み）

> ルール5「中心の機能に触る前に、測る仕組みを作る」に沿って、AIの出力とコードの動きを確かめる方法をまとめる。2026年11月6日に、今の流れ（前提が要りそうな言葉を見つける）に合わせて書き直した。これまでの案（観点ごとに予測する形）のテストはやめた。

## 1. 方針

- **文章ではなく条件を検査する。** AIが返した言葉を正解の文と比べず、「出てほしい言葉が出たか」「出てはいけない言葉が出なかったか」「形が正しいか」を判定する。
- **AIとコードを分けてテストする。**
  - **コード**（毎回・無料）：AIの出力の検査、質問リストの並べ替え、聞き直さない、取り消す、呼び出し回数の上限など。
  - **AI**（変えたときだけ・費用がかかる）：本物の Gemini に例文を渡し、条件を満たすかを見る。
- **中心の機能を変える前後に回す。** 指示文・モデル・検査を変えたら、AI評価テストを回してから入れる。

## 4. 実行のしかた

## 5. いつ回すか・合否の目安

- **回すとき**：指示文（`prompt.ts`）・モデル（`GEMINI_MODEL`）・検査（`detection.ts`）を変えたとき。
- **コード側**：100% 通ること。
- **AI評価テスト**：まずは 10件中 8件以上を目安にする（目安は人が決める）。落ちたケースは、返った言葉を見て、指示文を直すか、ケースが厳しすぎないかを考える。
- ルール3に沿い、「たぶん直る」と思ったら直す前に試して確かめる。2〜3回指示文を直しても効かなければ、設計（観点リストを入れる など）を見直す。

### 数や量の決まり方（2026-11-08 追加）

Tomo の依頼：「ロキソニンテープを10枚処方して」と言われたら、「10枚」で「分かりますか？」と聞いてほしい。1日に何枚使うか、貼りすぎると体に悪いので、処方する枚数の決まり方を知りたい。特定の薬ではなく、一般に使えるようにする。

**指示文に足したこと**（`prompt.ts` の言葉を探す指示文、「対象」）：数や量（〇枚・〇本・〇錠・〇日分・〇mL など）で、その数が何から決まったか（1回にどれだけ・1日に何回・何日分・どこに使うか）が、発言にもこれまでの会話にも出ていないものは、数の部分を返す。決まり方が発言や会話に出ている数は返さない。
