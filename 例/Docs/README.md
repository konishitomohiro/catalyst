# README（AI向け入口）

このアプリを開発するAIは、作業を始める前にこの文書を読む。

## 読む順番

1. 方向：誰のために何を作るか、決めたことと理由
2. 今できること：作る機能と、扱わない範囲
3. 仕組み：AIとコードの線引き、データの形、言葉の対応表

## 守るルール

1. 作る前に、方針を人と相談して決める。
2. 決まったことは、確認を待たずに文書に書いてから見せる。
3. 「たぶん直る」と思ったら、直す前に実験で確かめる。2〜3回で効かなければ設計を疑う。
4. AIには文章を書かせる。選択と判断はコードがする。
5. 中心の機能に触る前に、測る仕組みを作る。
6. デプロイまでを1つの作業にする。

扱わない範囲にある機能は、人に確かめずに足さない。

## AIが自分で決めてよいこと／人に聞くこと（案）

| 自分で決めてよい | 人に聞く |
| --- | --- |
| 変数名・関数名・ファイル内の構成 | 観点の追加・変更 |
| 不具合の原因の調査 | 扱わない範囲の変更 |
| テストの追加 | 画面に出す文言、医療に関わる表現 |

## 正本

正本は、このフォルダにあるMarkdownファイル。変更はすべてここに書く。

Google Drive との分け方（2026年11月6日）：

- **アプリの中身**（方向・決定の記録・仕組み・デザイン・テスト・提出・直すこと）は、このフォルダが正本。Drive と食い違ったら、こちらを正とする。
- **チームの運営資料**（日々の記録・予定表・写真・公式資料）と**提出物のファイル**は Drive に置く。Drive で決まったアプリの中身は、ここに書き写す。

2026年11月7日に追加：GitHub に慣れていないメンバーのために、大事な文書は Drive「ハッカソン11月」の「01_アプリの決めごと（GitHubの写し）」に、Google ドキュメントの**写し**を置く（読む用）。

- 写すもの：1_方向・2_今できること・3_仕組み・4_デザイン・5_次にやること・8_提出・9_直すこと。各写しの先頭に、いつの時点の写しかと、正本へのリンクを書く。
- 写しは書き換えない。直したいことは写しへのコメントで受け取り、ここ（GitHub）を直してから写しを作り直す。
- これらの文書を大きく変えたら、写しも作り直す（Drive の入口は「00_はじめに読む」）。
- このリポジトリは公開なので、個人の連絡先やチーム内の資料の中身は書かない。

オンラインのドキュメント（claude.ai）は、これらのファイルの元になったコンセプトシート。今後は更新しないので、内容が食い違ったらMarkdownを正とする。
